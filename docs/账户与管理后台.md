# 账户与管理后台 · 设计方案（待拍板）

> 状态：方案，未实现 · 日期：2026-10-20 · 维护：本仓库 `docs/`
> 原则：**普通用户不登录也能用全部公开内容**（产品介绍、下载、更新日志、隐私政策）；登录只解锁「和我有关的东西」。

## 1. 现状

| 能力 | 现在在哪 | 谁能看 |
|---|---|---|
| 产品页、下载、更新日志 | 本站 `mackhan.github.io`（GitHub Pages，纯静态） | 所有人 |
| 应用内「有新版本」 | 本站 `/updates/<产品>/changelog.json` | 所有人（应用读取） |
| 埋点数据 | 私有仓 `mackhan/pa-stats`（`data/<应用>/<年-月>.jsonl`，由 tauri-commerce `analytics` 上报） | 只有仓库成员 |
| 统计页 | 2026-10-20 已从公开站撤下；聚合逻辑保留在 `stats.py` | — |
| 付费 / 激活 | 规划用 Lemon Squeezy License API（见 `release-site-design.md` 第 7 节） | — |

GitHub Pages 的限制：**站上任何文件对所有人可见，没有服务端**，不能靠「藏起来的页面」做权限——权限必须落在数据那一端。

## 2. 注册登录对用户有什么用（参考同类网站）

| 好处 | 参考 | 对我们的意义 | 优先级 |
|---|---|---|---|
| **我的授权 / 设备管理**：看买过什么、激活了几台设备、自助解绑换机、找回激活码 | Raycast、JetBrains 账户、Setapp、Vibe Island | 付费上线后最高频的客服问题（换机、丢码）变自助 | ★★★ 付费上线时必做 |
| **新版本 / 公测通知**：订阅某个产品，有新版本或开放公测发邮件 | Linear Changelog 订阅、Arc、TestFlight 公开链接 | 生命树外部测试、PromptLedger 新版直接触达老用户 | ★★★ |
| **反馈与需求投票**：提问题、给需求点赞、看处理进度 | Canny、Linear 公开路线图、Raycast 的 feature request | 替代「发邮件」这种黑盒，知道大家最想要什么 | ★★ |
| **跨设备同步**：设置、提示词档案等跟账户走 | Raycast Cloud Sync、Bear | PromptLedger 手机端目前靠 GitHub 私仓同步，门槛高；账户可替代 | ★★ |
| **抢先体验 / 优惠**：早鸟价、老用户升级优惠、邀请返利 | Setapp、Paddle 优惠码 | 有购买记录才能做老用户优惠 | ★ |
| 评论更新日志 | 少数站点有 | 价值低、要审核，不做 | — |

**不做的事**：不强制登录下载；不收集与功能无关的信息（只要邮箱，或微信 / GitHub 一键登录）；不做社交。

## 4. 做在官网里，还是单独地址？——**用户账户放官网，管理后台单独地址**

| | 同站（`/account`、`/admin`） | 单独地址（如 `admin.<域名>` 或独立部署） |
|---|---|---|
| 用户体验 | 好：顶栏「登录」，同一个站 | 用户不需要感知 |
| 安全 | 管理端代码随公开站下发，攻击面和公开站绑在一起 | 管理端代码不对公众发布，可单独加访问限制 |
| 发布节奏 | 改后台要重新发布整站 | 互不影响 |
| GitHub Pages 能否承载 | 用户账户页可以（数据在后端、按身份返回）；管理页放上去等于公开代码 | — |
| 行业做法 | 用户中心常在主站（Raycast `/account`、JetBrains Account 子域） | 后台几乎都独立（Stripe Dashboard、Vercel、Lemon Squeezy 后台都不在官网路径下） |

**结论**：
- **普通用户**：官网顶栏加「登录 / 我的」，账户页可以挂在官网（或跳到账户后端所在域名，体验上像一个站）。
- **管理员**：后台用**单独地址**，不在官网导航里出现；权限由后端校验角色，不靠地址保密。

## 5.5 已上线：管理员后台 P0（2026-10-20）

- **地址**：<https://mackhan.github.io/pa-admin/>（独立仓库 `mackhan/pa-admin`，不在官网导航里，`noindex`）
- **登录**：填一个 GitHub 令牌（建议 Fine-grained：只给 `mackhan/pa-stats`，Contents 只读；要管权限再加 Administration 读写）
- **使用统计**：浏览器直接读私有数据仓聚合——累计设备、7 / 30 日活跃、近 30 天柱图、版本 / 系统 / 事件分布；
  口径与本仓库 `stats.py` 一致（`pa-admin/tests/parity.js` 对拍）
- **权限管理**：能看后台 = 对 `pa-stats` 有读权限；页面里直接邀请 / 移除协作者
- **数据来源**：PromptLedger 0.5.0 起默认开启匿名埋点（只有应用名 / 匿名安装 id / 事件 / 版本 / 系统 / 时间），
  启动 1 分钟后首报、之后每 6 小时一次
- **公开站**：不再放任何统计数字（2026-10-20 已撤下 /stats）

### 令牌怎么配、丢了怎么找回

登录时页面会逐项自检并打勾/打叉：`令牌格式 → 令牌有效（列出 scope）→ 能看到私有仓 → 能读 data/ → 能否管协作者`，卡在哪一层、该改哪个开关都写在打叉那一行下面。常见对应关系：

| 看到的现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 令牌无效或被吊销（HTTP 401） | 粘贴不完整、已过期、已 Regenerate | 重新生成一个 |
| 看不到私有仓（HTTP 404） | Fine-grained 令牌没勾这个仓库 | Repository access → Only select repositories → `mackhan/pa-stats` |
| 看得到仓库但读不到 `data/`（HTTP 403） | 令牌没有 Contents 权限 | Permissions → **Contents: Read-only**，改完要重新生成令牌（旧令牌不会自动升级） |
| 不能管理协作者（HTTP 403） | 没有 Administration 权限 | 加 **Administration: Read and write**；只看统计可以不管 |
| 经典令牌（`ghp_…`）不够用 | 经典令牌按 scope 授权 | 至少要 `repo` scope |

**令牌只有创建那一刻显示一次**，GitHub 之后任何页面都不再显示明文（只列名字、权限、过期时间）。所以：

- 丢了就在同一页点 **Regenerate**（名字和权限不变，立刻作废旧令牌），或删掉重建；
- 后台登录后右上角会显示掩码令牌（`ghp_…abcd`），点一下即复制整串，可以存进密码管理器；它同时记住在这台电脑的浏览器里，点「退出」即清除；
- 本机 App 自己上报用的那个令牌随时可取：`gh auth token`（存在 `~/.prompt-archive/settings.json` 的 `analytics_token`）。这个令牌是全权限的，**只在本机用**，不要填到任何网页里。

## 6. 推荐实施顺序

- **P0 管理员统计页（零后端，可以马上做）**：单独地址的静态页（不链接、不进官网导航），管理员首次打开时填一个只读 GitHub token，页面直接读私有仓 `pa-stats` 并在浏览器里聚合（`stats.py` 的逻辑移植过去）。**数据权限由 GitHub 私有仓保证**——没有仓库权限的人拿到页面也看不到任何数字。
- **P1 账户体系**：按第 5 节拍板的后端，先做「登录 + 我的授权 / 设备 + 新版本订阅」，同时把管理后台的「用户与权限」接上；统计页并入后台。
- **P2**：反馈与投票、跨设备同步（PromptLedger 手机端从 GitHub 私仓迁到账户）。
