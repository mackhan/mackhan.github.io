# 版本与更新日志规则（所有产品通用）

一句话：**版本号和更新内容只有一个源头，就是产品自己的仓库**。本仓库（网站）不手抄，只搬运。

## 为什么要有这条规则

以前版本号和更新日志写在两个地方：App 里一份、网站上一份。两边靠人记着同步，结果是网站长期停在旧版本
（KVMini 网站停在 0.3.4 时，App 已经是 0.4.6），访客看到的永远是过时的信息。

同一份更新日志现在有三个出口，所以错了就是三处一起错：

- 网页上的产品页与更新日志页
- 应用内「有新版本」弹窗：读 `https://mackhan.github.io/updates/<产品>/changelog.json`
  （`build.py` 从 `content/changelog/<产品>.md` 生成，和网页同源）
- App 自己的「更新日志」页面（App 内部的另一份，是本文件的上游）

## 版本号

1. 唯一真相是产品仓库里的版本字段（KVMini / IDPhoto 是 `Cargo.toml`，MovieBox 是 `package.json`，
   生命树是 Xcode 的 `MARKETING_VERSION`）。升版本时产品仓库里所有登记过的位置必须一起改
   （KVMini 是 5 处：`Cargo.toml`、`package.json`、`src-tauri/tauri.conf.json`、
   `src/index.html` 的 `app-version`、`main.rs` 的 `get_changelog()`；漏改会让发布预检失败）
2. 网站上的版本号**由更新日志最新一条决定**（`build.py` 取 md 里最新的 `## vX · 日期`），
   不单独维护一个「当前版本」字段
3. 日期格式 `YYYY-MM-DD`，与产品仓库里的更新日志日期一致
4. 版本号写法与产品一致：产品发 `1.0.0` 就写 `1.0.0`，不要自创 `1.0`

## 更新日志格式

`content/changelog/<产品>.md`（中文）与 `content/changelog/en/<产品>.md`（英文）：

```
## v1.2.3 · 2026-10-22
### 新功能
- …
### 改进
- …
### 修复
- …
```

- 分组标题固定三种：中文「新功能 / 改进 / 修复」，英文「New / Improved / Fixed」
- **中英文必须版本对版本、日期对日期**（`build.py` 的 `check_translation` 会拦，构建直接失败）
- 写用户语言：不写内部术语（Bug 编号、构建、签名、单测、重构），不写根因分析
- 与实际不符的内容不写（例：KVMini 0.4.0 的付费条目因付费墙未启用，网站上不列）

## 怎么同步：两条路

### 路 A：产品能生成 manifest.json（推荐）

产品发布时生成一份机器可读清单，里面是版本号、发布日期、中英文更新内容。网站拉它自动写入
`site.json` 和两份 changelog。

- 生成脚本放在产品仓库：KVMini `scripts/gen-manifest.mjs`、MovieBox `scripts/gen-manifest.mjs`
- 清单字段：`version`、`released`、`platforms`、`downloads`（带 `label_en`）、`links`（带 `label_en`）、
  `changelog`（中文分组）、`changelog_en`（英文分组，没有就留空——英文得人工补）
- 清单要能被公开访问：MovieBox 用自己的 GitHub Pages，KVMini 作为 Release 资产分发
  （它的 github 远端只用于分发，代码不推，所以不走 raw.githubusercontent）
- 网站侧：`python3 tools/sync_product.py <产品id>`，`--check` 只对比，`--all` 补历史缺口，
  `--local <文件>` 用本地清单（产品发布脚本直接调这个，不等 CDN）

### 路 B：产品没有清单（用草稿）

App 内更新日志是 Rust 的 `ChangelogEntry` 或 Swift 的 `ChangelogEntry(...)` 时：

```bash
python3 tools/import_changelog.py kvmini     ~/Documents/Git/KVMini/src-tauri/src/main.rs
python3 tools/import_changelog.py snipscribe ~/Documents/Git/OnenoteCopy/src-tauri/src/changelog.rs
python3 tools/import_changelog.py lifetree   <...>/AppChangelog.swift --lang both
```

输出到 `drafts/`（不入库），人工改写后再并入 `content/changelog/`。

## 新增一个产品时

1. `site.json` 的 `products` 里加一条，有英文文案的字段都要带 `_en`
2. `content/changelog/<id>.md` 与 `content/changelog/en/<id>.md` 各建一个（顶部写注释说明来源）
3. 产品仓库加清单生成脚本，发布时带上；把清单地址填进 `site.json` 的 `manifest` 字段
4. 跑一次 `python3 tools/sync_product.py <id>` 验证，再 `python3 build.py` + 单测
